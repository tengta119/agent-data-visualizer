# ADR-009 开发环境采用非 rm 命令全量一次性审批

日期：2026-10-06

状态：已采纳

## 背景

硬件查询等命令未命中原来的有限 allow/prompt 前缀列表。用户要求只拒绝包含独立 rm 命令或词的执行，其余命令全部由用户审批，并确认不按任意 rm 子串匹配，避免误拒绝 format 等普通单词。

## 决定

- 在 dev YAML 中将 local/remote allow 清空，local/remote prompt 配置为 `['*']`；remote host 列表为 `['*']`，允许指定任意非空、实际在线的远程客户端。
- prompt 中的 `*` 表示全量审批模式：忽略 allow 规则，整段命令按大小写不敏感的独立 rm 词匹配拒绝，包括路径、rm.exe 和简单引号拼接/转义；其余有效命令均要求一次性审批。管道、重定向及多行脚本不再因普通模式的解析限制被提前拒绝。
- 仍校验命令非空、长度、NUL、命令类型与 host 一致性，保留审批二次审查、超时、容量与取消机制；同步接口无审批通道时不执行 Prompt 命令。
- 含宿主 ShellExecutor 工具的批次按顺序执行，避免并行调用竞争默认单请求一个待审批槽位。其他非浏览器工具仍按原规则并行。
- 不修改类默认前缀策略，因此未启用该显式模式的 test/prod 配置沿用原行为。

## 取舍

由用户对每段完整命令进行一次性决定，减少持续维护命令前缀清单的需要。rm 检查是文本词匹配及简单归一化，并非完整 shell 解释器，不能宣称为删除操作防护沙箱；其他删除命令也按用户要求进入审批。一次批准不代表执行成功，也不建立永久授权。

## 验证

补充规则、审批前不执行与批准后执行、Shell 批次顺序和上下文测试源码。按仓库要求，构建和测试由开发人员手动执行，实施时未运行。
